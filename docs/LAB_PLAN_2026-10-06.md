```bash
cd ~/Desktop/multi-drone-testbed
python3 - <<'EOF'
import sys, re, numpy as np
sys.path.insert(0,'tools'); import analyse_trochoidal as A
import glob, os
f=max(glob.glob('logs/hw/*.txt'), key=os.path.getmtime)
txt=open(f).read()
blk=re.search(r'initial positions from config:\n((?:#   \w+: \[.*\]\n)+)',txt).group(1)
marks={m[0]:np.array([float(m[1]),float(m[2])]) for m in
       re.findall(r'#   (\w+): \[([-\d.]+), ([-\d.]+)\]',blk)}
reals=re.search(r'real drones\s+(.*)',txt).group(1).split(',')
cols,D=A.load_record(f)
print(os.path.basename(f))
for r in reals:
    i=r.split('=')[0].strip()
    p=np.array([D[0,cols.index('x_'+i)],D[0,cols.index('y_'+i)]])
    d=np.hypot(*(p-marks[i]))
    other=min((np.hypot(*(p-marks[k])),k) for k in marks if k!=i)
    flag='OK' if d<0.10 else f'*** WRONG MARK -- nearest is {other[1]} at {other[0]*100:.0f} cm ***'
    print(f'  {i}: on floor at {p.round(3)}, {d*100:5.1f} cm from its mark   {flag}')
EOF
```

Under 10 cm on every real drone or the flight does not count. Fix and refly.

## Known traps

- **`crazyflies.yaml` lives in two places.** Editing the repo copy does nothing
  until you `sudo cp` it to `/opt/ros/$ROS_DISTRO/share/crazyflie/config/`. If
  drone_2 will not connect, this is why.
- **drone_2 enabled but unpowered stalls the server.** Disable it for the
  one-drone blocks or leave it powered on the floor.
- **The hexagon config's own launch comment is wrong** (`cf_name:=drone_1,drone_4`).
  Use `drone_1,drone_2`.
- **`hw_drone`, `cf_name` and `mocap_name` are matched positionally.** Getting
  the order wrong drives the wrong agent from the wrong aircraft, which is a
  different failure from the mark swap and looks similar.
- **Firmware setpoint mode persists across restarts.** If a drone behaves
  unlike its siblings, power-cycle it before blaming the config.
- **`takeoff_height:=1.5,0.8`** puts drone1 above drone4. The first value goes
  to the first name in `hw_drone`.
